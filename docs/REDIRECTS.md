what Google recommends when mapping an old URL to its replacement.

link to either form redirects in a single hop — no redirect chains.

## Adding a redirect

1. Add **both** forms of the old path (with and without the trailing slash) to the `redirects` array
   in `vercel.json`, and set `"permanent": true`.
2. Point it at a route that actually exists. Every destination can be checked against the build
   output with `npm run check:redirects`.

## Fragments are not supported in destinations

Vercel redirect destinations do not reliably carry a `#fragment`. Where an old URL should land on a
specific section, redirect with a query parameter and let the page upgrade it to an anchor. The one
current example: `/digital-literacy-returning-citizens-50-plus/` redirects to
`/training?section=digital-literacy-50-plus`, and `src/pages/TrainingPage.tsx` scrolls to that
element and rewrites the address bar to `/training#digital-literacy-50-plus`.

## Do not add a catch-all rewrite

Known routes are real prerendered files (`dist/about.html`, `dist/news/<slug>.html`, …) and unknown
paths must fall through to `dist/404.html` so they return **404** instead of 200. A catch-all
rewrite to `/index.html` would restore the old "everything returns 200" behaviour.
